# Add Note Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Anki notes to a selected deck with a shared Flutter form driven by Anki's note type metadata.

**Architecture:** The Flutter feature calls a note repository; the repository encodes pinned Anki protobufs and invokes the existing bridge. Rust resolves the three required Backend service methods from the pinned descriptor set.

**Tech Stack:** Flutter/Dart, protobuf, Rust, Anki rslib backend.

**Spec:** `docs/superpowers/specs/2026-09-27-add-note-design.md`

## Global Constraints

- Use the pinned Anki source and generated protobuf descriptors.
- Keep the existing native backend as the only backend on desktop and mobile.
- Add no product dependencies.
- Write and verify a failing test before production changes.

## Review Focus

- Note type selection is disabled while Anki is loading or saving; test that a pending save cannot change the payload's fields.
- A backend validation failure must preserve the entered field values; test the error path.
- An empty collection with no note types must show a recoverable explanation; test the empty state.
- Field labels and ordering must follow Anki's returned note; test dynamic field order.
- Saving must target the deck the user opened even if Anki's default deck differs; assert the request's deck ID.
